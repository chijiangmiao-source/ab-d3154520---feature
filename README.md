# 轨道应急规程 · 危险可达性安全审计

在处理节点可**调用具名子规程**并在返回后转入**续点**的模型下，安全官在
上行前需确认：**根入口是否会经任意嵌套层数抵达危险节点**。本服务按下推
系统（PDS）语义精确求解，避免有限展开漏掉故障链。

## 解决思路（不截断栈、不规定递归深度、不把调用边当普通图边）

把系统建模为下推系统，控制位置是“当前帧正在执行的节点”，栈存放各帧待
返回的续点：

| 事件 | 迁移 |
|---|---|
| 普通跳转 `n→m` | `(p.n, γ) → (p.m, γ)` |
| 调用 `n→q`，续点 `c` | `(p.n, γ) → (q.e_q, (p,c)·γ)`（压栈） |
| 正常返回 | `(p.n, (p',c)·γ) → (p'.c, γ)`（弹栈，精确配对） |
| 危险节点 | 终止目标 |

以**单调饱和求最小不动点**得到栈无关摘要：

- `same_succ[x]`：与 `x` 同栈内容下一帧可达的配置——普通跳转边，以及当
  被调帧入口 `can_return` 时才成立的“整段调用返回”边 `调用点→续点`；
- `reach[x]`：同栈净效果不变的帧内传递闭包；
- `can_return[x]`：能否在本帧层级执行到 `return`；
- `danger[x]`：经帧内危险节点，或帧内某调用点的被调帧入口危险。

调用只有在被调帧**确实能返回**时才接回续点，因此纯无界自递归
（`l0: call loop→l1; l1: return`）不会被无根据点亮 `can_return`，其后的
危险续点正确判为**不可达**。配置集合有限，结论单调有界，必在有限步收敛，
对无界递归成立。

危险可达时，在有限摘要图上取最短事件路径，把 `调用点→续点` 边递归展开为
“下钻被调帧—跑到 `return`—弹栈回续点”，重放出一条**有限且每步带调用栈**
的普通跳转 / 调用 / 返回链。

## 处置方案：抵达同一危险节点的最低总代价

审计判定危险可达并冻结后，安全官可提交处置方案：填写稳定处置标识，
并为原规程中**每个可执行跳转、调用或返回节点**填写非负整数处置代价，
服务以 **min-plus 饱和**确认抵达同一危险节点的最低总代价：

    ret[x]   从配置 x 执行到本帧 return 的最优 (总代价, 事件数) 摘要
    dng[x]   从配置 x 抵达危险节点的最优 (总代价, 事件数)

    return 节点   ret = (c,1)
    danger 节点   dng = (0,1)
    jump n→m      ret/dng = (c,1) ⊕ ret/dng[m]
    call q,cont   ret = (c,1) ⊕ ret[q.e] ⊕ ret[cont]
                  dng = (c,1) ⊕ min( dng[q.e], ret[q.e] ⊕ dng[cont] )

调用仅在被调帧**确实能返回**（`ret[q.e]` 有限）时才接回续点：任意嵌套
调用下返回精确配对，调用边绝不被当作普通跳转，也绝不只重排既有最短
事件链。所有代价非负，从 ∞ 单调递减迭代必收敛到最小不动点——零代价
递归只停在 ∞，不会振荡。存在多条最低代价链时，依次按**事件数**与
**节点标识序**稳定裁决；重放逐步展示累计代价、调用栈及调用/返回/
跳转事件。

## API

- `GET /health`：可用性。
- `GET /`：录入与结果页。
- `POST /api/analyze`：提交 `{audit_id, root_entry, procedures[]}`。
  - 一次性返回全部错误：缺失/重复标识、悬空入口/续点/目标、无效节点类型、
    根入口错误（HTTP 400）。
  - 同 `audit_id` 同载荷重传：回放冻结结论（`replayed:true`）。
  - 同 `audit_id` 改换载荷：明确拒绝（HTTP 409）。
  - 草稿改动在前端清除旧显示。
- `GET /api/evidence/{audit_id}`：刷新/重启会话后按审计标识读取相同证据；
  未知标识 404。
- `POST /api/dispose`：对已冻结的危险可达审计提交
  `{disposal_id, audit_id, costs:[{node, cost}]}`。
  - 一次性返回全部错误：来源结论安全、代价表节点遗漏/重复、未知节点、
    非法代价（HTTP 400）；来源审计不存在（HTTP 404）。
  - 同 `disposal_id` 同载荷重传：回放冻结方案（`replayed:true`）。
  - 同 `disposal_id` 改换来源或代价表：明确拒绝（HTTP 409）。
  - 任何拒绝都不改写原审计与已冻结方案；编辑草稿在前端清除旧显示。
- `GET /api/disposal/{disposal_id}`：刷新后按处置标识读取完全相同的证据；
  未知标识 404。

节点类型：`jump`（字段 `next`）、`call`（字段 `target`、`cont`）、
`return`、`danger`。规程至多 12 份。

## 运行

零第三方依赖，仅需 Python 3.11（亦提供容器方式）。

```bash
# 本地直接运行（端口可配置）
PORT=8080 python -m app.server
# 浏览器打开 http://localhost:8080

# Docker Compose（宿主端口可配置）
HOST_PORT=9090 docker compose up web

# 一次性 verify 服务：构建检查 + 代码测试 + HTTP 冒烟，跑完按状态码退出
docker compose up --build verify      # 全部通过退出码 0，否则 1
# 或本地：
python verify.py
```

`verify.py` 覆盖：递归返回后才进入危险续点（逐步链与每步栈）、悬空调用
拒绝、同载荷冻结回放/改换载荷拒绝/按标识取证、无界递归即时收敛，以及
处置方案——递归子规程返回后进入危险续点的最低成本、零代价递归收敛、
处置标识冲突拒绝、原危险审计仍可读取、按处置标识取回相同证据。
